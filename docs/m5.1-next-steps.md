# M5.1 — state and next steps

Working notes for picking M5.1 (parameter-generic analysis, DESIGN_GUIDE.md section 18) back
up. Delete this file when the work it describes is done.

## Done and committed

- Generic units in EIR, specialisation at elaboration, symbolic widths in the frontend.
- The library boundary: a design is first analysed against its input libraries without their
  sources, binding unknown instantiations to library units; anything that needs the sources
  falls back to reading them (`Session::analyseWithoutLibrarySources`).
- Exit criterion 2: the frontend test `AHundredWidthsOfOneModuleAreOneTranslation`.
- Exit criterion 3: `tests/designs/generic-units.sh` and each design's `generic.txt`.
  common_cells is at 9 of 106 parameterised modules; taxi at 12 of 36.
- `lib list` marks each unit `(generic)` or `(a parameterisation of X)`.
- Constant functions (D4): a package's function becomes its own unit (`isFunction`), run by
  the VM at elaboration through `session::ConstantFunctionRunner`. It is checked against the
  call slang evaluated (ENZ3017). The frontend's own checks evaluate it with slang.

## WIP in the commit that adds this file — not yet verified

The aim is that a constant replication or concatenation whose shape a parameter decides
(`{W{1'b1}}`, `{{W-1{1'b0}}, 1'b1}`) no longer keeps a unit specialised. common_cells'
cc_counter, cc_stream_join and tc_sync are refused only for that.

- `SystemVerilogFrontend.cpp`: the `MultipleConcatenationExpression` case is removed from
  `widthOrStructureMentions`. The translator already refuses a runtime replication whose
  width a formal decides. With only that change, all 1202 tests passed.
- `ProcessTranslator::foldFormalConstant`: folds such a constant into one annotated constant,
  at the start of `translateConcatenation` and `translateReplication`.
- `tests/golden/sv/generic_widths.sv`: the case gains `lowest` and `filled` outputs that use
  those constants. Enzan and iverilog 12 agree on the output.

**Open problem:** with the extended test, `accumulator` comes out *specialised* (check with
`enzan analyse --out-lib` and `enzan lib list`), so the case no longer tests a generic unit.
Before `foldFormalConstant`, the cause was `usedAsNumber` from
`translateReplication -> constantValueOf`. Its cause after `foldFormalConstant` has not been
looked at yet. Likely suspects:

- the `W/2` and `W - W/2` counts not lowering in `ParameterLowering` (Divide on an `int`);
- the fold not being reached because `namesFormal(expression)` is false for the outer
  concatenation;
- `agrees` disagreeing because the folded constant's annotation differs.

To get the refusal reasons, use the debug-print approach of the earlier sessions: prints at
each `return false` in `makeGeneric`, and at the `buildUnit` and `agrees` exits. Then run the
full suite, the common_cells design run, and the SystemVerilog-off build before splitting
this into proper commits.

## Next steps, in order of what they unlock in common_cells

Refusal counts are from the current run, over 106 parameterised modules.

1. **Type parameters (60 modules).** This is a design decision for Jan. A packed type
   parameter (`parameter type T = logic [W-1:0]`) could be a width formal whose actual is
   the type's width. The guide currently says a type parameter keeps a unit specialised.
2. **Constant replication and concatenation (3).** The WIP above.
3. **Range selects with parameter bounds, `x[W-1:0]` in expressions (`SimpleRangeSelect`, 7).**
   The selects machinery (`Location`, `noteWrite(Number, Number)`) already takes symbolic
   positions; the source rule refuses before it is tried.
4. **Typedef dimensions over parameters (`typedim`, 8).** `SymbolicWidths::packed` reads a
   declaration's own dimension syntax; a typedef's would have to be followed too.
5. **if and loop generate (8 + 5).** These need EIR to hold the construct, and specialisation
   to expand it (guide section 18, "Generate constructs"). This is the largest item.
6. **No value formals (17).** Modules whose parameters are all type parameters are covered
   by step 1.

## Known limitations to record or fix

- A constant function that never returns hangs elaboration: the kernel has no instruction
  budget, and `RunInterrupt` is polled only between time slots.
- Only a package's functions become units. A module's own functions, and those of the
  compilation unit, keep their callers specialised.
- The no-sources library path falls back to reading sources for a hierarchical reference
  into a library instance (`DisallowRefsToUnknownInstances`), for packages and interfaces
  of the library, and for a port connection that is an expression.
- A function unit built during a trial that is then discarded stays in the design, and so
  in the library. This is harmless, but `lib list` shows it.
